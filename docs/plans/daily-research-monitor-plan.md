# Implementation Plan: Daily Research Monitor

> Generated by `pact-codex-plan-mode` on 2026-06-14
> Status: PENDING APPROVAL

## Summary

Build a daily, discovery-only literature monitor for this repository. The monitor should detect new papers related to the project's epistemic-humility research trajectory, save candidate metadata with provenance, and queue candidates for human review.

The monitor must not modify `archive/docs/protocols/phase1/PROTOCOL.md`, hypotheses, falsifiers, headline matrix, evidence tables, or inclusion criteria. It surfaces candidates; Joseph or another named human decides whether each candidate is included, excluded, deferred, marked duplicate, or held for a future revision.

#### Design Approach

Use a small repo-native monitor subsystem under `library/`, separate from experiment execution under `archive/experiment/phase1/` and separate from the `synaptic-tuner` submodule.

Recommended component flow:

1. Source adapters fetch recent metadata from approved sources.
2. A normalizer maps source-specific payloads to a canonical paper record.
3. A deduper checks prior monitor state, `library/manifest.yaml`, and existing notes.
4. A trajectory matcher assigns advisory relevance scores and reasons.
5. A queue writer records candidates with provenance.
6. A human review step sets the decision state.
7. A separate guarded promotion step may add human-included papers to `library/manifest.yaml`.

#### Key Decisions

| Decision | Options | Recommendation | Rationale |
|----------|---------|----------------|-----------|
| Repo boundary | `library/monitor/`, `automation/`, `research-inbox/` | `library/monitor/` | This is literature operations and should align with the existing library surface. |
| Scheduler | Manual CLI, local task, GitHub Actions | Manual CLI first, then GitHub Actions if approved | Proves behavior before unattended daily automation. |
| Queue target | Repo YAML/JSONL, GitHub Issues, hybrid | Hybrid or GitHub Issues-first | Issues reduce daily commit churn; repo files give durable audit state. |
| Source scope | arXiv-only, arXiv+OpenAlex, broader | arXiv-only or arXiv+OpenAlex v1 | Lower credential and rate-limit burden while covering current AI research. |
| Ranking | Lexical rules, embeddings, LLM triage | Transparent lexical/topic scoring first | Easier to audit and less likely to redefine scope silently. |
| PDFs | Store, link, quarantine | Link only by default | Avoids copyright, malware, and repository bloat risk. |

Allowed status values:

- `pending`
- `include`
- `exclude`
- `defer`
- `needs_fulltext`
- `duplicate`
- `watch`

Guardrail contract:

- The monitor may write only to allowlisted monitor output paths and, if approved, GitHub Issues.
- The monitor may not write to `archive/docs/protocols/phase1/PROTOCOL.md`, evidence tables, experiment configs, or run matrix files.
- Human `include` means "approved for library admission or follow-up," not automatic protocol revision.

## Synthesized Implementation Roadmap

### Consensus Approach

All consultants agreed on a discovery-only monitor with explicit human review. The core guardrail is separation between:

- detection: automated, advisory, provenance-rich
- decision: human, reasoned, auditable
- protocol change: never automated, requires signed revision/changelog when applicable

### Conflicts

| Conflict | Severity | Resolution Needed |
|----------|----------|-------------------|
| GitHub Issues vs repo-file queue | Major | User decision. Issues reduce daily commit churn; repo files improve local auditability. |
| arXiv-only vs multi-source v1 | Major | User decision. arXiv-only is simpler; multi-source improves recall. |
| abstracts/PDF storage | Major | User decision. Links-only is safest; abstracts improve review; PDFs should be off by default. |
| daily automation immediately vs manual-first | Minor | Recommendation: manual/dry-run first, then scheduled job. |

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Protocol drift | Medium | High | Discovery-only scope, write allowlist, protocol immutability tests, signed revision rule. |
| Review queue noise | High | Medium | Narrow v1 queries, daily cap, relevance reasons, no-op notifications suppressed. |
| False negatives | Medium | High | Multiple query profiles, overlap window, periodic profile review, optional multi-source expansion. |
| Duplicate papers | High | Medium | Stable IDs first, title fingerprint fallback, mark duplicates with provenance. |
| API/rate-limit failures | Medium | Medium | Backoff, partial failure reporting, offline default tests, artifacts/log summaries. |
| Credential leakage | Low | High | Prefer credential-free sources, secrets only in env/GitHub secrets, redacted logs. |
| Copyright/PDF exposure | Medium | High | No PDF commits by default; links and metadata first; verify abstract caching terms. |
| Prompt injection from papers | Low in v1 | Medium | No LLM triage in v1; if added, treat paper content as data only. |
