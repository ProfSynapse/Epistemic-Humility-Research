## Code Phase
**Effort**: Medium

#### Files to Create

#### Implementation Sequence
1. Enumerate candidate result directories and write a schema audit.
2. Normalize rows into a single master table with run metadata.
3. Validate row alignment before paired comparisons.
4. Compute known/unknown behavioral states:
   - Known refused = over-refusal.
   - Known answered correct = useful answer.
   - Known answered incorrect = capability or answer failure.
   - Unknown refused = accurate IDK.
   - Unknown answered = contract-level hallucination exposure.
5. Add deterministic question tags: wh-word, number/date/person/place, definition, list, comparison, temporal/future, subjective/normative, entity-heavy.
6. Compute paired transitions:
   - Unknown refused -> answered: lost accurate IDK.
   - Unknown answered -> refused: gained IDK.
   - Known refused -> answered correct: useful over-refusal recovery.
   - Known refused -> answered incorrect: over-refusal reduced but not useful.
   - Known correct -> refused/incorrect: capability degradation.
7. Generate representative row examples for high-signal transitions.

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Row misalignment across arms | Medium | High | Validate `(eval_set, row_index)` plus question/id/label/source before transitions |
| Lower over-refusal mistaken for improvement | High | High | Separate useful recovery from answered-incorrect transitions |
| Refusal heuristic misses nuanced IDK wording | Medium | Medium | Recompute scorer outputs and manually audit high-impact examples |
