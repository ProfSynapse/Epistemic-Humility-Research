Launch only after the merged clean SFT model passes a sanity eval.

Use the merged clean SFT path as `--model-name`; this keeps the base/reference
state aligned with the merge-first protocol.

```powershell
docker run -d --name eh-clean-sft-dpo-seed1-full-<timestamp> `
  --gpus all --ipc=host --entrypoint python3 `
  -e HF_HOME=/workspace/repo/.cache/hf `
  -e HUGGINGFACE_HUB_CACHE=/workspace/repo/.cache/hf/hub `
  -v "F:\Code\Epistemic-Humility-Research:/workspace/repo" `
  -w /workspace/repo `
  unsloth/unsloth:latest `
  synaptic-tuner/Trainers/dpo/train_dpo.py `
  --model-name /workspace/repo/<MERGED_CLEAN_SFT_MODEL> `
  --local-file /workspace/repo/scratch/schema_response_confidence/qwen3-4b-instruct/dpo_response_confidence_train.jsonl `
  --output-root /workspace/repo/scratch/schema_response_confidence/runs/schema_clean_sft_dpo_seed1_full `

  --batch-size 2 --gradient-accumulation 4 `
```

## Eval Gates

Before downstream DPO/KTO/GRPO:

- run a mixed SelfAware smoke on the merged clean SFT model
- require 100% JSON `answer` + `response_confidence` coverage
- inspect unique confidence values and band counts
- compare known over-refusal and unknown answering against Amendment D/E controls

After each downstream run:

- run the same mixed SelfAware smoke first
- do not proceed to full eval if scalar confidence collapses or behavior is
  obviously off against its nearest control
