## Question & Hypothesis

**RQ.** The v2-trained model's emitted `response_confidence` is collapsed to a
near-constant ~0.82 (std 0.015), AUROC ~0.56 at ranking its own correct vs wrong
answers, ECE ~0.14 — yet an internal L35 doubt axis ranks the same items cleanly
(correct > wrong > refused > unknown) and is near-calibrated by linear readout
(ECE ~0.004; see [[caution-vs-doubt-knowledge-gate]]). The model *knows* but does
not *say*. Can a reward redesign close that knowing–saying gap by making
**internal–output coherence the optimum** rather than a hand-specified target?

**Root cause (diagnosed, not hypothesized).** v2 shapes confidence toward a
**fixed per-cell target keyed to the realized cell** (`known_correct → 0.82`,
`known_wrong → 0.22`, …). The model cannot observe its correctness at generation
time, so it cannot condition the confidence token on it; with ~96% of answered
knowns correct, emitting the majority target (~0.82) for every answer is
**reward-optimal** → collapse. The confidence term (weight 0.6) is also dominated
by behavior (±2.0).

**Hypothesis.** Replacing the fixed target with a **proper scoring rule** (Brier)
of confidence against realized **appropriateness**, scored against a
**per-question** target, makes a constant sub-optimal and the true probability
`p(appropriate | question)` optimal. Because that probability is already encoded
on the internal doubt axis, the cheapest way to earn the reward is to **route the
internal signal to the output token** → calibration improves (ECE ↓, correct-vs-
wrong AUROC ↑) without degrading behavior (over-refusal / unknown-answer rates).

**Falsifiers.**
- Calibration does not improve (ECE/AUROC unchanged) under v3 → the signal is not
  routable by this objective; suspect the confidence token is generated by a
  pathway that cannot read L35, or the weight is too low.
- Behavior degrades (over-refusal or unknown-answering rises) → confidence term
  is over-weighted; behavior-dominance invariant violated.
- `internal` target mode diverges from `group`/`outcome` results → the internal
  probe is not a faithful proxy for realized appropriateness (informative either
  way).

## Design

New reward `experiment/phase1/grpo/humility_reward_v3.py` (v2 untouched). Behavior
magnitudes carried over from v2 (dominant). Confidence term = Brier proper score
scaled to ±`confidence_weight` (raised 0.6 → 1.2, still < behavior magnitudes);
only exact 0/1 degeneracy is penalized (the v2 anti-high-confidence pressure is
removed so a 96%-correct known may legitimately state ~0.95).

Per-question target (`target_mode`):
- **`outcome`** — per-completion realized appropriateness (0/0.5/1); proper in
  expectation, needs no grouping.
- **`group`** (default) — the GRPO group's mean appropriateness for the prompt
  (variance-reduced difficulty target), computed from the completions TRL already
  passes the reward; no extra forward pass, no probe.
- **`internal`** — a precomputed per-prompt doubt-axis probe estimate passed as an
  `internal_confidence` dataset column (literal "align to the internal
  representation"); tests faithfulness vs calibration.
- **`blend`** — convex mix of group and internal.

**Recommendation:** lead with `group` (anchors to ground truth; pulls the output
toward the already-near-calibrated internal axis automatically). Run `internal` as
a science arm: does faithfulness-to-internals converge to the same calibration as
calibration-to-truth? Convergence is strong evidence the introspective signal is
genuinely calibrated; divergence is itself a finding.

Arms (proposed v3 training panel, one seed each, mirror the v2 cell otherwise):
`v3-group`, `v3-internal`, `v3-blend`, with `v2` as the baseline already trained.

## Prerequisites & Gating

- `internal` / `blend` modes need an offline pass that writes `internal_confidence`
  per train prompt from the L35 doubt-axis logistic probe (reuse
  `phase3_latent_knowledge_probe` + the ka-vs-ur axis). Gated, GPU for extraction.
- TRL reward signature only receives completions/prompts/metadata — NOT hidden
  states. So `internal` targets MUST be precomputed offline and passed as a
  dataset column; do not attempt in-loop activation reads (would require a
  submodule engine change, which is out of bounds).
- **Governance:** v3 is a NEW cell. It does not edit the protocol-locked v2 reward
  or any locked run-matrix cell. A v3 training run needs explicit user sign-off
  and a governed amendment with changelog. No training launched by drafting this.

## Runbook

1. (done) Draft `humility_reward_v3.py` + `tests/test_humility_reward_v3.py`
   (18 tests; includes a direct collapse-resistance test — calibrated per-prompt
   confidence beats a flat 0.82 on both easy and hard prompts).
2. CPU reward preflight on a sample of v2 rollout debug rows: re-score with v3,
   confirm behavior ordering preserved and confidence-target spread is non-degenerate.
3. (gated) Offline `internal_confidence` column build for the train set.
4. (gated, sign-off) Train `v3-group` seed-1; eval calibration (ECE, correct-vs-
   wrong AUROC, confidence std) + behavior (over-refusal, unknown-answer rates)
   vs v2.
5. Re-probe the v3 model: did the L35 doubt axis → output coherence improve
   (does emitted confidence now track the doubt projection)?

## Validation contract

- Reward unit tests green (behavior dominance + proper-score optimum + collapse
  resistance + target-mode resolution).
- Pre-run: behavior-ordering invariant holds on re-scored v2 rollouts.
- Post-run definition of done: v3 emitted confidence std ≫ 0.015 AND
  correct-vs-wrong AUROC > v2's 0.56 AND ECE < v2's 0.14, with over-refusal and
  unknown-answer rates no worse than v2 (behavior not traded for calibration).
- Power note: the correct-vs-wrong eval needs more wrong-answered rows than the
  16 currently available (see [[caution-vs-doubt-knowledge-gate]]).

## Variations

- `confidence_weight` sweep (1.0 / 1.2 / 1.5) — learnability vs behavior dominance.
- `target_mode` ∈ {group, outcome, internal, blend}.
- SFT-side calibrated confidence labels (seed the model out of the collapsed basin
  before GRPO; links to the response-confidence SFT line, session 0018).
