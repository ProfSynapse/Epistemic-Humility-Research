## Abstract

This paper studies policy-adherent tool-calling agents in customer-service domains. It argues that standard prompt-only agents leave task state implicit in transcripts, which can cause stale-state decisions and syntactically valid but policy-violating tool calls. LedgerAgent adds an inference-time structured ledger for observed task state and a policy gate that checks environment-changing calls against ledger-grounded predicates before execution.

## Summary

LedgerAgent is an inference-time scaffold for tool-using agents. It stores successful read-tool returns in a typed state ledger, renders that ledger into subsequent prompts, and gates write actions with deterministic policy predicates over observed state. The model weights, decoding, and tool schemas are unchanged, so the method tests whether explicit state representation and action-boundary checks improve reliability without extra model calls.

The paper evaluates LedgerAgent on four customer-service domains from tau2-Bench and tau-Trait: airline, retail, telecom, and telehealth. LedgerAgent improves average pass^k over standard function calling across several model families, with larger gains on stricter multi-trial consistency metrics and on tasks requiring environment-changing tool calls.

## Relevance to experiment

This is not a humility-training effect study and should not enter `effects.csv`. It is relevant as adjacent agent-safety infrastructure: it shows how explicit state representation and deterministic gates can prevent policy-violating actions when LLMs operate tools over multi-turn state. For later agentic epistemic-humility work, it suggests a design pattern for separating observed state, model-generated plans, and executable action checks.

- Tool-calling agents can fail even after retrieving the right records because relevant task state remains implicit in transcript history. [[tool-calling-agent]] [[task-state-ledger]]
